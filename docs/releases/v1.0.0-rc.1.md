# `v1.0.0-rc.1` release notes

> **Unofficial project.** unifi-cli is an independent community tool and is not affiliated with, endorsed by, or sponsored by Ubiquiti Inc. UniFi is a trademark of Ubiquiti Inc.

`v1.0.0-rc.1` is the first release-candidate contract for safely managing a
local UniFi Network controller from the terminal. It targets UniFi Network
10.3.58+, uses the official local integration API for stable behavior, and
keeps all non-DNS writes experimental.

## Highlights

- Stable official reads for sites, devices, connected clients, networks, WiFi
  broadcasts, ports, modern firewall zones/policies, all DNS policy types,
  network resolvers, and derived health.
- Stable official DNS A-record create/update/delete with input validation,
  returned-ID capture for creates, immutable targets for update/delete,
  post-write verification, and no ambiguous retries.
- Experimental official Network/WiFi/device/firewall writes plus isolated
  experimental legacy compatibility operations.
- Schema-v1 JSON envelopes, no raw controller-payload mode, and version/commit/
  build-date/Go-version reporting.
- Verified TLS by default, custom CA support, redirect rejection, API-key native
  storage, and plan/yes/experimental/force gates.

## Compatibility status

The minimum supported target is UniFi Network 10.3.58. The implementation is
validated locally against synthetic fixtures derived from that official
schema. UniFi Network 10.4.57 is in the target range, but fresh live proof for
this RC remains a pre-publication release gate. See
[Compatibility](../compatibility.md); do not infer live compatibility from a
passing local suite.

## Safety boundaries

- Every mutation plans first; nothing applies without `--yes`.
- `--dry-run` always wins.
- Every non-DNS write requires `--experimental` to apply.
- High-impact and destructive applies require `--force` while `safe_mode` is
  enabled.
- DNS writes are A-record only.
- Non-DNS live mutation testing requires a dedicated sacrificial controller
  with disposable configuration and must never target a production-like
  network.
- Action output with `{"accepted":true}` does not claim asynchronous
  completion.

Review the complete risk matrix and resource limits in the
[README](../../README.md) before applying any write.

## Install after publication

```bash
go install github.com/noahjenkins/unifi-cli/cmd/unifi@v1.0.0-rc.1
unifi --version
unifi version --json
```

Alternatively, download the archive for the operating system and architecture
from the GitHub release, verify it against the published SHA-256 checksums,
extract it, and place `unifi` (or `unifi.exe`) on `PATH`.

## User verification checklist

- [ ] `unifi --version` reports exactly `v1.0.0-rc.1`, not `dev`.
- [ ] `unifi version --json` reports schema version `1` and non-empty version,
      commit, build date, and Go version fields.
- [ ] The downloaded archive matches the published SHA-256 checksum.
- [ ] `unifi --help` shows the unofficial-project disclaimer and does not show
      a raw-payload flag.
- [ ] The controller runs UniFi Network 10.3.58 or newer.
- [ ] Configuration contains a bare host, valid port, positive timeout, and
      verified TLS (`insecure: false` or a custom CA).
- [ ] `unifi login` stores the API key in the native keyring (or an explicitly
      selected protected-file fallback).
- [ ] `unifi auth status --json`, `unifi site list --json`, and
      `unifi system health --json` succeed before any plan is considered.
- [ ] A mutation is first run without `--yes` and its plan is reviewed.
