# `v1.0.0-rc.2` release notes

> **Unofficial project.** unifi-cli is an independent community tool and is not affiliated with, endorsed by, or sponsored by Ubiquiti Inc. UniFi is a trademark of Ubiquiti Inc.

This candidate freezes the planned v1 command and schema-v1 contracts. It
targets the official local UniFi Network 10.4.57 integration API.

## Release contract

- Stable reads cover the documented inventory, firewall, DNS, switching,
  RADIUS, and health resources.
- Stable writes cover A, AAAA, CNAME, MX, TXT, SRV, and forwarded-domain DNS
  policies.
- Every non-DNS write remains experimental. Classic firewall and
  switching/RADIUS writes are unsupported.
- Personal WLAN passphrases use only a hidden prompt or bounded stdin.
- JSON output validates against [`schemas/schema-v1.json`](../../schemas/schema-v1.json).

## Qualification evidence

Local formatting, unit, schema, documentation, coverage, release-contract,
module, race, and vulnerability gates must pass on the exact release commit.
The designated Apple M4 Pro darwin/arm64 host recorded these three-sample
medians on 2026-08-17:

| Workload | Median time | Median allocation | Budget |
|---|---:|---:|---:|
| 10,000-item official collection | 13.040375 ms | 5,503,224 bytes | Less than 2 s and 256 MiB |
| 1,000 official detail reads, four workers | 86.633583 ms | 44,379,176 bytes | Less than 10 s and 256 MiB |
| Warm `unifi --help` | Less than 10 ms timer resolution | Not measured | Less than 500 ms |

The macOS native-keyring save/load/overwrite/delete/missing-key round trip
passed with a unique synthetic entry that the test deleted. Windows Credential
Manager and Linux Secret Service also passed as hosted CI gates on the exact
candidate head.

The final candidate passed all 19 configured read-only checks on UniFi Network
10.5.67; the empty DNS collection was the single allowed `not_configured`
result. After separate approval, disabled and uniquely named A, AAAA, CNAME,
MX, TXT, SRV, and forwarded-domain policies each passed plan, create, exact
read, update, exact read, captured-ID-only delete, and absence verification.
The final DNS collection exactly matched the empty baseline. The controller's
self-signed certificate required the recorded explicit `insecure: true`
exception; verified TLS remains the default. No fixed-IP or other non-DNS live
write was run or claimed.

SRV qualification confirmed that `domain` is the base domain and `_service`
and `_protocol` are separate official fields. The CLI rejects a duplicated
`_service._protocol` prefix locally before any request.

## Install after publication

```bash
go install github.com/noahjenkins/unifi-cli/cmd/unifi@v1.0.0-rc.2
unifi --version
unifi version --json
```

Confirm `v1.0.0-rc.2` resolves to the protected-main release commit shown by
the GitHub release. The tag is controlled by the NoahJenkins GitHub account and
is not cryptographically signed. For downloaded archives, verify the published
SHA-256 checksum, provenance attestation, and CycloneDX SBOM before installation.
The tagged source install's detailed build information reports
`v1.0.0-rc.2`, but its `commit` and `build_date` remain `unknown`. Verified
archives carry the authoritative full build metadata with their checksums,
SBOMs, and provenance. See the short-version known issue below.

## Known issue found after publication

A tagged source install reports the correct `v1.0.0-rc.2` value from
`unifi version --json`, but the short `unifi --version` root flag reports
`dev`. Release archives are not affected. RC.3 supersedes this candidate and
corrects the short flag without changing controller behavior.

## User checks

- [ ] `unifi --version` reports `v1.0.0-rc.2`, not `dev`.
- [ ] The controller runs UniFi Network 10.4.57 or newer.
- [ ] Verified TLS or a trusted custom CA is configured.
- [ ] `unifi auth status --json`, `unifi site list --json`, and
      `unifi system health --json` succeed before a mutation plan is reviewed.
- [ ] Every mutation is first run without `--yes` and its plan is reviewed.

The complete provider, controller, artifact, and publication gates are in the
[maintainer release checklist](../maintainers/release-checklist.md).
