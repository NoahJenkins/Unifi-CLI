# `v1.1.0-rc.1` release notes

> **Unofficial project.** unifi-cli is an independent community tool and is not affiliated with, endorsed by, or sponsored by Ubiquiti Inc. UniFi is a trademark of Ubiquiti Inc.

`v1.1.0-rc.1` is the first candidate for `v1.1.0`. It adds experimental
commands and local configuration tools to the `v1.0.0` contract. It targets
UniFi Network 10.4.57 or newer. The stable surface is unchanged: official
typed reads and the seven official DNS policy writes. Every new write is
experimental. See [`CHANGELOG.md`](../../CHANGELOG.md) for the complete list.

## New

- Named non-secret controller profiles (`config profile list|show|select`)
  and the local-only `unifi doctor` readiness check.
- Experimental known-client fixed-IP inventory (`client fixed-ip list|get`).
  Set/clear can target known offline clients, and `set --network` selects a
  network when the stored record has none.
- Experimental firewall policy create with one exact source IPv4 address or
  source IPv4 subnet, one exact destination IPv4 address, and one exact TCP
  destination port.
- Experimental WLAN access-point selection (`--broadcasting-ap`, `--all-aps`).
- Experimental `network update --mdns-forwarding=true|false`. `network list`
  and `network get` show mDNS forwarding state.
- Official HTTP 400 validation errors return `validation_failed` with bounded,
  sanitized controller `code` and `message` fields.

## Fixed

- Firewall create and protocol update send the official uppercase
  named-protocol discriminator (`TCP`, `UDP`, `ICMP`, `ICMPV6`). Earlier
  builds from `main` sent lowercase names, which UniFi Network 10.6.109
  rejected before creation. `v1.0.0` did not include the exact-filter create.

## Platform change

This release is built with Go 1.27.3. macOS binaries require macOS 13 Ventura
or later; they no longer run on macOS 12 Monterey.

## Qualification

The candidate source must pass formatting, unit, schema, documentation,
coverage, release-contract, module, race, vulnerability, six fuzz targets,
release-host performance, native-keyring, and hosted operating-system gates.
Publication must independently build and compare all six native archives,
execute each on its native hosted runner, publish matching SHA-256 checksums
and CycloneDX SBOMs, and attach provenance attestations.

On the designated darwin/arm64 release host (Apple M4 Pro), the three-sample
medians were 13,230,917 ns and 5,376,616 bytes for the 10,000-item collection
benchmark, 74,337,958 ns and 37,924,888 bytes for the 1,000-detail-read
benchmark, and 0.00 seconds for warm help. All release-host performance
budgets passed.

On 2026-10-29, the read-only live suite passed against UniFi Network 10.6.109:
19 checks passed and the empty DNS collection returned the allowed
`not_configured` result. A read-only inspection of existing firewall policies
on that controller found the same named-protocol and exact-filter document
shape that the CLI sends. The local controller used the explicit insecure-TLS
exception for its self-signed certificate; verified TLS remains the default.

No live write was run for this candidate. The exact-filter firewall create,
fixed-IP, WLAN, and network mDNS writes have no sacrificial-controller
qualification and remain experimental. See
[Compatibility](../compatibility.md) for exact limits.

## Install after publication

```bash
go install github.com/noahjenkins/unifi-cli/cmd/unifi@v1.1.0-rc.1
unifi --version
unifi version --json
```

Both version interfaces must report `v1.1.0-rc.1` for the tagged source
install. Its `commit` and `build_date` remain `unknown`. Verified release
archives carry authoritative version, commit, build date, checksums, SBOMs,
and provenance.

The account-controlled tag is unsigned. Confirm it resolves to the protected
main commit shown by the GitHub release before installation.
